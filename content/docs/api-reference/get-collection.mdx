Returns the current state of a payment. Same response shape as
[creating a payment](/docs/api-reference/create-checkout).

<Tabs items={['cURL', 'Node.js', 'Python']}>
<Tab value="cURL">
```bash
curl https://connect.tchokopay.com/v1/collect/REQ-1785296850838-A5303B \
  -H "Authorization: Bearer tchoko_live_..."
```
</Tab>
<Tab value="Node.js">
```js
const res = await fetch(
  `https://connect.tchokopay.com/v1/collect/checkout/${reference}`,
  { headers: { Authorization: `Bearer ${process.env.TCHOKOPAY_API_KEY}` } },
);
const payment = await res.json();
```
</Tab>
<Tab value="Python">
```python
response = requests.get(
    f"https://connect.tchokopay.com/v1/collect/{reference}",
    headers={"Authorization": f"Bearer {api_key}"},
)
payment = response.json()
```
</Tab>
</Tabs>

## Response

`200 OK` — identical shape to [`POST /v1/collect/checkout`](/docs/api-reference/create-checkout#response).

Scoped to your own account: a reference that exists but belongs to another merchant
returns `404`, exactly like a reference that doesn't exist at all — so this endpoint can
never be used to probe whether a reference exists.

## Errors

| Status | Meaning |
|---|---|
| `401` | Missing, invalid, or revoked API key. |
| `404` | No payment with this reference on your account. |
