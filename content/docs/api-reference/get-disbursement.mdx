Returns the current state of one of your payouts. Scoped to your own account — another
merchant's reference comes back as `404`, not `403`, so nobody can probe whether a
reference exists.

## Request

<Tabs items={['cURL', 'Node.js', 'Python']}>
<Tab value="cURL">
```bash
curl https://connect.tchokopay.com/v1/disburse/PO-1787962449863-7B361B \
  -H "Authorization: Bearer tchoko_live_..."
```
</Tab>
<Tab value="Node.js">
```js
const res = await fetch(
  `https://connect.tchokopay.com/v1/disburse/${reference}`,
  { headers: { Authorization: `Bearer ${process.env.TCHOKOPAY_PAYOUT_KEY}` } },
);

const payout = await res.json();
```
</Tab>
<Tab value="Python">
```python
response = requests.get(
    f"https://connect.tchokopay.com/v1/disburse/{reference}",
    headers={"Authorization": f"Bearer {payout_key}"},
)
payout = response.json()
```
</Tab>
</Tabs>

## Response

`200 OK`

```json
{
  "reference": "PO-1787962449863-7B361B",
  "status": "SENT",
  "amount": 25000,
  "currency": "XAF",
  "recipientPhone": "670000000",
  "recipientName": "Amina Njoya",
  "merchantReference": "payout_4417",
  "providerReference": "MMH17797898332",
  "awaitingReview": false,
  "statusReason": null,
  "createdAt": "2026-08-29T01:34:09.863Z"
}
```

## Status values

| Status | Means | Your money |
|---|---|---|
| `PENDING` | Accepted and funded. Either queued to go out, or waiting for review. | Reserved |
| `SENT` | Handed to the network, which accepted it. Not yet confirmed delivered. | Reserved |
| `PAID` | Landed. The recipient has it. | Gone |
| `FAILED` | The network didn't complete it. | **Still reserved** |
| `REJECTED` | Declined during review. | Back in your balance |

<Callout>
**`SENT` is deliberately not `PAID`.** Mobile money networks confirm asynchronously, so
the network accepting a payout and the recipient receiving it are different events —
sometimes minutes apart. We don't collapse them, because your code will branch on this.
</Callout>

<Callout type="warn">
A `FAILED` payout **keeps your money reserved**. It does not go back automatically.

That's deliberate: when a dispatch fails we often can't tell whether the network took the
money or not, and returning funds we may already have sent is the one mistake with no way
back. TchokoPay retries it or returns it explicitly, and you'll get a `payout.failed`
webhook either way.
</Callout>

## Errors

| Status | Meaning |
|---|---|
| `401` | Missing, invalid, or revoked API key. |
| `403` | Your key doesn't have the **Send payouts** permission. |
| `404` | No payout with that reference on your account. |
