Every network the platform supports, across every country.

```bash
curl https://connect.tchokopay.com/v1/providers \
  -H "Authorization: Bearer tchoko_live_..."
```

```json
[
  { "provider": "mtn_cm",    "name": "MTN MoMo",     "method": "MOBILE_MONEY", "country": "CM", "supportsPayin": true, "supportsPayout": true },
  { "provider": "orange_cm", "name": "Orange Money", "method": "MOBILE_MONEY", "country": "CM", "supportsPayin": true, "supportsPayout": true },
  { "provider": "bank_gh",   "name": "Bank Transfer", "method": "BANK",         "country": "GH", "supportsPayin": false, "supportsPayout": true }
]
```

| Field | Description |
|---|---|
| `provider` | The code to send as `provider` when you collect or disburse. |
| `name` | What the network calls itself. Show this to your customer, not the code. |
| `method` | The class — `MOBILE_MONEY` for every network on it. It cannot tell two networks apart; `provider` is the field that can. |
| `country` | `null` for a borderless provider. |
| `supportsPayin` | Can you collect through this provider right now. |
| `supportsPayout` | Can you disburse through this provider right now. Not guaranteed to match `supportsPayin` — see below. |

<Callout type="warn">
  Some providers are one-directional. `bank_gh` above disburses to a Ghanaian bank
  account but does not collect; another provider might collect and not disburse. Call this with the direction you need in mind, not just the country and
  method — a `POST` against a provider that doesn't support that direction returns
  `PROVIDER_DIRECTION_NOT_SUPPORTED`, not a silent failure. See
  [errors](/docs/guides/errors-and-limits#codes).
</Callout>

<Callout type="warn">
  This is the catalogue — what the **platform** supports. What **your account** may use
  can be narrower. Build your picker from
  [`GET /v1/account/providers`](/docs/api-reference/account-providers) instead, or your
  customers will be offered networks that refuse them.
</Callout>
