Lists every payin method your customers can currently use, platform-wide — useful if you
want to show a payer, in your own UI, what to expect before they even reach the hosted
checkout page.

```bash
curl https://connect.tchokopay.com/v1/account/providers \
  -H "Authorization: Bearer tchoko_live_..."
```

## Response

`200 OK`

```json
[
  { "providerCode": "mtn_cm", "method": "MOBILE_MONEY", "country": "CM", "available": true, "reason": null },
  { "providerCode": "orange_cm", "method": "MOBILE_MONEY", "country": "CM", "available": true, "reason": null }
]
```

| Field | Description |
|---|---|
| `providerCode` | Internal provider identifier. |
| `method` | Payment method — `MOBILE_MONEY`, etc. |
| `country` | ISO country code this channel serves. |
| `available` | Kept for forward compatibility — currently always `true`. |
| `reason` | Kept for forward compatibility — currently always `null`. |

<Callout type="info">
  This endpoint is scoped to **collection**: every channel listed here already accepts
  payin. It won't list a provider that only disburses — for the full catalogue including
  one-directional providers, with explicit `supportsPayin`/`supportsPayout` flags, use
  [`GET /v1/providers`](/docs/api-reference/providers) instead.
</Callout>

<Callout type="info">
  This reflects what's open platform-wide, not something specific to your account —
  every approved merchant sees the same list.
</Callout>
